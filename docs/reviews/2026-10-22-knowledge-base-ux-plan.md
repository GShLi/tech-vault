# 知识库交互调整方案

状态：已实施并完成本地自动化与真实依赖验收；结果、测试范围及生产边界见 [实施验收记录](2026-10-22-knowledge-base-implementation.md)。连续上传锁等待修复见 [修复记录](2026-10-22-ingestion-busy-fix.md)。以下保留方案作为验收依据。

## 1. 列表与详情原位编辑

- 列表删除“编辑”按钮，保留名称进入详情和归档入口；归档放入“更多”菜单。
- 详情标题后添加带“编辑知识库”提示的铅笔图标，仅有管理权限的用户可见。
- 点击后标题原位置切换为 Arco Input，描述原位置切换为 Textarea；同一区域显示“保存”“取消”。
- Enter 保存名称，Escape 取消；描述框 Enter 正常换行。取消恢复原值，保存中禁用重复操作。
- 名称去除首尾空格后校验必填、最多 120 字符；错误显示在编辑区内。
- 使用现有版本条件更新。发生版本冲突时保留草稿，提示重新载入最新内容后核对，不自动覆盖。
- 切换知识库、团队或离开页面时，对未保存修改提供放弃确认。
- 新建弹窗继续保留，但分离列表加载错误与表单保存错误，增加一致的字段校验。

## 2. 批量上传

### 用户流程

1. 从知识库详情进入上传页，使用路由中的知识库作为唯一目标上下文，显示知识库名称及返回入口。
2. Arco Upload 支持多选及拖拽多个文件；一次至少可选择 200 个文件。单文件继续遵守现有 50 MiB 限制，批次总大小和数量上限由服务端配置并在选择区明确展示。
3. 展示待上传清单：文件名、大小、状态、进度、错误原因、移除/重试操作。大量文件采用分页或虚拟列表。
4. 产品、版本、可见性和数据分类作为本次批量上传的共同默认值，并明确提示适用范围。
5. 点击“开始上传”，建议默认同时上传 3 个文件，其余排队；失败只重试对应文件，不重传成功文件。
6. 重名文件明确提示，并允许移除；本轮不自动覆盖旧文档或推断为新版本。

### 批次与任务

- 每次提交创建一个持久化上传批次，关联团队、知识库、发起人、预期文件清单；每个文件保留独立解析任务。
- 批次记录成功接收、上传失败、待处理、处理中、成功和处理失败数量。列表状态区分上传完成、处理进行中、全部完成、部分失败。
- 上传请求使用批次文件标识做幂等关联，防止网络超时后重试导致重复文档和任务。上传后不再依赖浏览器页面存活来完成解析。
- 单文件上传成功后可直接进入其任务详情；多文件进入该批次的处理进度页，点击具体文件再进入现有任务详情。
- 批次详情通过服务端查询持久化数据，不能仅以 URL 携带 200 个任务 ID。支持刷新、失败筛选和单项重试。
- 关闭页面不会中断已经接收的文件处理；尚未上传的本地文件重新进入时需要重新选择，不宣称支持刷新后自动续传。

### 后端配套调整

当前 `/docs/upload` 一次接收一个文件，并返回 document / document_version_id / ingestion_run_id；可沿用单文件传输方式，增加批次关联，避免一个超大 multipart 请求承载所有文件。

当前入库流程持有团队处理锁，每个文档发布完整团队索引快照。需要把解析、切分、向量化准备与索引发布分离：同团队有序调度；正常排队不计为失败；模型并发按设备容量限制，初始可串行。对一批准备成功的文档合并发布索引，避免 200 次完整索引发布。批次在上传阶段结束后收敛处理结果，准备失败的文件单独记录并可重试。

发布期间继续提供旧的有效索引；新索引校验并完成切换后，文档才显示“可用于问答”。批次需处理索引发布失败、部分文件失败、任务取消和进程恢复，不能把“已上传”标成“解析成功”。

## 3. 上传结束弹窗

弹窗触发条件：本次上传队列中的请求全部结束，不等待后台解析结束。每批只弹一次。

- 标题：全部成功时“上传完成”；部分失败时“本次上传已结束”。
- 正文示例：“已上传 198 个文件，2 个上传失败。已上传文件正在后台解析，完成后可用于问答。”
- 操作一：**继续上传**。停留当前页，清空成功项，保留失败项及其原因；保留当前知识库和公共表单设置。
- 操作二：**查看处理进度**。单文件直接跳对应任务，多文件跳批次进度页。
- 所有文件均上传失败时不提供无效任务跳转，留在页面显示错误及“重试失败项”。
- 网络响应不确定时先查询批次接收状态，再决定是否重试；“上传成功”不会重复提交。

## 4. 新建知识库默认模型策略

- 新建知识库默认设为 `external_allowed`（允许外部模型），后端创建逻辑和数据库模型默认值保持一致。
- 新建表单提示默认策略，并提供创建后进入策略设置的路径。
- 允许外部模型仍受平台/团队策略、供应商准入与数据分级约束；如果上级仅允许本地模型，界面同时说明当前实际限制。
- 本要求针对新建知识库，已有知识库策略不批量改写。

## 5. 移除 GitHub 来源能力

- 删除知识库详情“来源”入口、来源统计和来源卡片，上传方式统一为本地文件上传。
- 删除 GitHub 来源页面与路由、前端 API 方法、专用类型和相关测试。
- 移除 GitHub 来源创建、同步、暂停、恢复等后端路由、任务分发、Worker 和同步服务；清理 GitHub 专用凭证/配置及失效模型引用。
- 同步更新 API 文档、产品页面说明、部署说明和测试，避免仅隐藏界面但后台仍可创建或同步。
- 已导入文档作为静态文档保留，旧连接和同步配置清理，不再执行自动同步。

## 6. 同步修复此前发现的问题

- 最近任务按当前知识库过滤，任务显示文档名称和处理阶段；进入任务中心时保留筛选。
- 成员管理移至独立管理区域，补充未保存提醒、成功反馈和移除自身访问权限时的影响提示。
- 详情突出文档列表，支持搜索及分页；文档、任务等分区加载和重试。
- 新建成功进入新库详情，提供上传和设置访问成员引导。
- 列表/详情切换加入请求作用域保护，防止旧请求覆盖新知识库数据。
- 归档确认补充访问影响与恢复能力说明；恢复入口作为独立功能处理，不能使用模糊文案暗示当前已支持。

## 验收重点

1. 列表不再出现编辑，详情原位编辑可保存、取消、校验和处理版本冲突。
2. 从任一知识库进入上传，目标正确；200 文件多选可排队，失败重试不重复创建文档。
3. 上传完成弹窗正确区分上传与解析，两个选项符合预期；批次任务页刷新后仍能查询状态。
4. 同团队并发批次不因正常排队耗尽重试，索引发布失败不影响旧索引可用性。
5. 新库默认允许外部模型，上级策略限制仍生效。
6. GitHub 界面、API 和后台同步入口全部移除，静态文档仍可访问。
7. 批量处理进行真实依赖验收，记录不同文件大小/格式、部分失败、网络中断和 Worker 重启结果，不仅验证 UI 能选择 200 个文件。
