# TechVault 全仓库代码审查与优化

日期：2026-10-22。审查基于当前工作区，保留了此前尚未提交的解析、入库及权限相关改动；未修改 `AGENTS.md`。

## 范围与方法

覆盖 `backend/app`、`frontend/src`、`deploy`、`scripts` 的源码目录、依赖方向、重复实现和复杂度热点，并结合测试、部署配置与已有 Java 文档验收记录复核。初始扫描包含 178 个源码/配置文件、39,009 行（排除测试文件、依赖、缓存及构建产物）。

方法包括 Python AST 函数长度/分支扫描、跨文件重复片段检查、Vue 模板组件扫描、关键业务路径人工阅读、前后端自动化回归和浏览器代表页面检查。分支统计包含嵌套函数及布尔表达式，仅用于排序热点，不等同于标准圈复杂度；没有据此宣称某个全仓库重复率或覆盖率。

重点维度：复杂度、重复度、职责边界、依赖方向、异步状态一致性、资源释放、检索数据完整性、可观测性、配置安全和前端加载成本。

## 本轮已修复与优化

| 编号 | 原问题与影响 | 实施位置与结果 |
| --- | --- | --- |
| F01 | 聊天独立维护 SSE 解析；CR/LF 跨网络分片时可能合并事件，读取器未释放 | `utils/sse.ts` 共用解析、跨分片换行处理、UTF-8 解码、失败取消及 finally 释放；聊天复用该模块 |
| F02 | 任务、审计、Trace 列表重复分页；团队切换后旧请求可能覆盖新数据 | `composables/useCursorList.ts` 统一游标、错误、去重和请求代次；切换团队立即清空，卸载后忽略迟到响应 |
| F03 | 聊天和评测复制供应商/模型筛选规则 | `useProviderSelection.ts` 共用启用状态、密钥、策略白名单和模型有效性判断 |
| F04 | 多个页面将非 ApiRequestError 异常置为 null，操作失败却无提示 | 页面及供应商表单复用 `normalizeApiError`，支持业务兜底消息 |
| F05 | 全部页面静态导入，入口包含大量未访问页面代码 | 33 个视图动态导入；最大 JS chunk 从约 820 KB 降至 331.29 KB（原始体积约下降 60%）；保留静态应用外壳 |
| B01 | 双引擎融合手动重建 RetrievedChunk，丢失父 Chunk、代际、关键词和证据信息 | `retrieval/engines.py` 使用 dataclasses.replace；共同命中时保留词法元数据，输入依赖改用 Retriever 协议 |
| B02 | 流式成功、失败及非流式成功重复拼装 Trace，字段容易漂移 | 提取 `rag/observability/trace.py` 的候选、上下文、改写和阶段耗时函数；详情/导出共用响应构造 |
| B03 | SSE done 与列表重复累加嵌套耗时；非流式成功漏存部分阶段耗时 | 统一父子阶段去重规则，保留测量阶段；相同目的多次网关调用累加，避免只留下最后一次 |
| B04 | Trace 持久化白名单丢弃 evidence_chunk_ids | 仅保留合法的当前 `chd_` ID，去重并过滤任意内容；仍不存正文 |
| B05 | 父上下文读取重复解析 JSON，额外读取实时行并逐父节点查询代际成员 | 分离 `_load_parent_family`；使用一次快照/成员查询，每条 JSON 解析一次；验证成员 ID 与快照一致，继续执行版本、范围、状态和偏移校验 |
| B06 | 仅设置 JWT 密钥即可使用默认管理员密码启动生产实例 | 非 development/test 环境拒绝默认或少于 12 字符的初始化密码；README 补充配置要求。不会自动修改已有账号密码 |

### 可维护性变化

- `ChatPage.vue` 从 2,475 行缩至约 2,384 行；抽离协议和选择策略后，页面仍包含较多会话、引用及布局职责。
- `chats.py` 从 1,857 行缩至 1,759 行；`ask` 从 562 行减至 533 行，流式响应构造从 597 行减至 568 行。
- `hydrate_parent_chunks` 从 60 行减至 44 行，快照读取移至独立函数；含生成代际时，SQL 查询从“实时行 + 全代际快照 + 每个父节点成员查询”变为一次快照/成员查询。
- 新增共享模块使总行数不一定下降；本轮重点是减少规则的重复维护点、保留数据及收敛职责。
